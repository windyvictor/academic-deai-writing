# 诊断模式：改前报告与改后复测

**适用**：用户要求先给诊断、审稿意见、问题清单、「先别改」，或稿件长、改动风险高、需要逐项核对。默认任务仍按 `SKILL.md` 的工作流程直接交付改稿，本模式是可选分支。

设计依据：`lieflat-less-ai-tone`（CC BY-NC 4.0，作者 shiujan）的「先检测、讲清依据、等确认、再改写与复测」流程。该技能对成稿强制两阶段确认；本技能只在用户要求诊断时启用，因为科研改写通常以拿到可继续修改的稿件为目的。

## 一、三层分工

| 层 | 判断对象 | 谁判 | 产出 |
|---|---|---|---|
| 形式层 | 可逐处数出的：翻案腔、结论提示冒号、顿号并列、相邻句同构、章节与版式 | 会话内模型逐条核对 | 可定位的命中清单 |
| 语义层 | 要理解句意的：术语是否漂移、连接词标称的关系是否成立、冒号属于哪一类、三连是否句法逐字复刻 | 会话内模型按封闭判据逐条判 | 每条一个标签 + 一句理由 |
| 人审层 | 比喻贴切度、案例是否凑数、研究贡献是否成立、证据是否充分、创新点能否扩张 | 作者 / 用户 | 只列出，不代判 |

**不引入通用中文检测脚本。** `lieflat-less-ai-tone` 的 `detect.py` 阈值来自中文自媒体语料，规则含「说白了」「拟人化喻体」等学术无关项，人类参考值也不适用于论文。把它的分值套到论文上会把语料偏差带进诊断。本技能用逐处核对替代脚本计数，用 `false-positive-guard.md` 约束处置。

语义层判断纪律：只按判据判，不按「像不像 AI」的整体印象；每条独立判断；拿不准选兜底标签；不自造标签。

## 二、改前报告（五项，缺一不可）

1. **方法与口径。** 说明检查了哪些维度、稿件字数与段落数、命中候选数量。区分「研究语料中的统计显著」与「本篇单次命中」；没做单篇检验就不宣称本文统计显著，也不判定作者身份。
2. **命中表。** 按维度列原始命中数、有效命中数、拟改数、保留数及理由类别。句长离散度、小节长度等整篇分布指标只报实测值与处置，不强造逐句命中数。命中为零的维度也列出。不同轮次口径不混算倍数。
3. **例句与改法。** 每个拟改维度摘 1–2 处可定位原句，说明命中机制、对论证或阅读的具体影响，再给可执行的改法。只给短句示意，不在此交付改后全文。保留事实、限定词与信息点，不写「改得自然些」这类空泛建议。
4. **排除项与范围。** 每个保留或排除的维度写清数量与理由类别，至少举一处可定位例句。对照 `false-positive-guard.md` 逐项确认已证伪特征与学术体裁例外。最后汇总拟改范围与保留边界。
5. **确认点。** 请用户对整套建议回复「按建议改」或提出调整，不逐条索要决定。发出报告后停在诊断阶段，收到回复前不改正文。

**命中清单不可静默删项。** 复核只能给每条标注「拟改 / 保留 / 误报 / 待核或人审」及理由，不能改写原始计数或把不想要的候选移出清单。语义层判为「不符合判据」也要计入原始候选到有效命中的差额。用户提供了文件时，保留可追溯的逐条结果。

**保留是需举证的例外。** 有效且可定位的命中默认列为拟改；本篇次数少或密度低只影响优先级，不单独构成保留理由。保留须指出该处的术语、引用、公式、逻辑连接或版式作用为何不可替换。判不准标「待核 / 人审」并展示原句。

## 三、收到确认后的改写与复测

- 只改用户接受或调整后纳入方案的项，每处改动能指出对应的报告项与具体原因；指不出就撤销。
- 改写遵守 `SKILL.md` 的三条红线与改写纪律，涉及引文、公式、代码、参考文献时不得改动其内容。
- 按与改前相同的口径复测：拟改项是否完成、误报是否说明、事实锚点是否保留、`false-positive-guard.md` 中的项是否被动过、保留项理由是否仍成立。
- 分布指标只给变化方向，不追求推到某个目标值；不循环改写直到「AI 率」下降。理由见 `evidence-and-policy.md`。
- 交付默认只给改后全文。用户要求对比时，再给前后对照与改动清单，标明每处「原文 → 改后 + 原因」。
